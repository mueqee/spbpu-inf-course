## 5. Шаблоны решений

### 5.1. Подсчёт чисел с заданными свойствами

```python
# Пример: найти количество четырёхзначных чисел, у которых сумма цифр = 15
# и каждая цифра нечётна

count = 0
for n in range(1000, 10000):
    digits = [int(d) for d in str(n)]
    if sum(digits) == 15 and all(d % 2 == 1 for d in digits):
        count += 1
print(count)
```

### 5.2. Перебор наборов с помощью itertools.product

```python
import itertools

# Пример: найти количество наборов (a, b, c), где a, b, c ∈ [1, 10],
# a + b + c = 15 и a * b * c чётно

count = 0
for a, b, c in itertools.product(range(1, 11), repeat=3):
    if a + b + c == 15 and (a * b * c) % 2 == 0:
        count += 1
print(count)
```

### 5.3. Перебор подмножеств через битовую маску

```python
# Пример: из набора [3, 7, 2, 9, 5, 1, 8, 4] найти количество подмножеств,
# сумма элементов которых равна 17

data = [3, 7, 2, 9, 5, 1, 8, 4]
n = len(data)
count = 0
for mask in range(1 << n):          # 2^n вариантов
    subset_sum = sum(data[i] for i in range(n) if mask >> i & 1)
    if subset_sum == 17:
        count += 1
print(count)
```

### 5.4. Задачи с исполнителем — рекурсивный подсчёт программ

Самый частый тип задания 23 на ЕГЭ — **исполнитель с командами**. Дан исполнитель с набором арифметических команд (например, +1, ×2, ×3). Нужно подсчитать количество программ, которые преобразуют начальное число в конечное, возможно, с ограничениями на **траекторию вычислений** (последовательность промежуточных результатов).

**Ключевая идея:** рекурсивная функция `f(x, y)` считает количество путей из `x` в `y`, применяя все доступные команды. Это и есть нисходящее динамическое программирование.

#### Тип 0: без ограничений на траекторию (базовый шаблон)

```python
# Исполнитель: команды +1 и ×2. Из 2 получить 8. Сколько программ?

def f(x, y):
    if x == y:       # дошли до цели — считаем этот путь
        return 1
    if x > y:        # «перескочили» — этот путь тупиковый
        return 0
    # применяем все команды и суммируем количество путей
    return f(x + 1, y) + f(x * 2, y)

print(f(2, 8))
```

**Правила построения функции:**
- Базовый случай «успех»: `x == y` → `return 1`
- Базовый случай «провал»: `x > y` (или `x < y` при движении вниз) → `return 0`
- Рекуррентное соотношение: применяем каждую команду и суммируем

#### Тип 1: траектория НЕ должна содержать число X

Добавляем запрещённое число в условие «провала»:

```python
# Команды: +1, ×2, ×3. Из 2 получить 20. Траектория НЕ содержит 11.

def f(x, y):
    if x == y:
        return 1
    if x > y or x == 11:   # «провал»: либо перескочили, либо наткнулись на запрет
        return 0
    return f(x + 1, y) + f(x * 2, y) + f(x ** 2, y)

print(f(2, 20))
```

Несколько запрещённых чисел — просто добавляем через `or`:

```python
if x > y or x == 9 or x == 16:
    return 0
```

#### Тип 2: траектория ДОЛЖНА содержать число X

Разбиваем путь на два отрезка: «от старта до X» и «от X до цели», перемножаем:

```python
# Команды: +1, ×2. Из 3 получить 37. Траектория СОДЕРЖИТ число 18.

def f(x, y):
    if x == y:
        return 1
    if x > y:
        return 0
    return f(x + 1, y) + f(x * 2, y)

# Количество путей 3→18 умножаем на количество путей 18→37
print(f(3, 18) * f(18, 37))
```

> Логика: каждый путь 3→18 можно продолжить любым путём 18→37. Правило произведения комбинаторики.

#### Тип 3: траектория ДОЛЖНА содержать X и НЕ должна содержать Y

Комбинируем оба приёма: разбиваем по обязательному числу X и запрещаем Y в каждом отрезке:

```python
# Команды: +1, +2, ×3. Из 2 получить 12. Траектория содержит 8 и 10.
# (два обязательных числа → три отрезка: 2→8, 8→10, 10→12)

def f(x, y):
    if x == y:
        return 1
    if x > y:
        return 0
    return f(x + 1, y) + f(x + 2, y) + f(x * 3, y)

print(f(2, 8) * f(8, 10) * f(10, 12))
```

#### Движение «сверху вниз» (исходное число больше конечного)

Если команды уменьшают число (–1, –2, //3), меняем знаки сравнения:

```python
# Команды: –1, –2, //3. Из 19 получить 3. Траектория НЕ содержит 9 и 16.

def f(x, y):
    if x == y:
        return 1
    if x < y or x == 9 or x == 16:   # провал: промахнулись мимо или запретное
        return 0
    return f(x - 1, y) + f(x - 2, y) + f(x // 3, y)

print(f(19, 3))
```

#### Когда нужна мемоизация (`@lru_cache`)

При большом расстоянии между числами или при множестве команд рекурсивное дерево разрастается, и одни и те же значения вычисляются повторно. Добавляем мемоизацию:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def f(x, y):
    if x == y:
        return 1
    if x > y:
        return 0
    return f(x + 1, y) + f(x * 2, y) + f(x * 3, y)

print(f(5, 52))
```

> `@lru_cache` автоматически запоминает результат каждого вызова и возвращает его при повторном обращении с теми же аргументами. Без него задача с числами ~50–100 может зависнуть.

## 6. Оценка сложности и риски превышения времени

| Размер перебора | Примерное время | Вывод |
|:---|:---|:---|
| до 10⁶ итераций | < 1 секунды | Безопасно |
| 10⁷ итераций | ~1–3 секунды | Допустимо |
| 10⁸ итераций | ~30 секунд | Опасно, нужна оптимизация |
| 10⁹ итераций | Минуты | Недопустимо — менять алгоритм |

> На экзамене: если перебор занимает больше 30 секунд, ищи способ сократить пространство поиска (ранний выход, `break`, предварительная фильтрация, перебор только части параметров с выводом оставшихся из уравнения).

## 7. Типичные ошибки

| Ошибка | Как избежать |
|:---|:---|
| Забыть импортировать `itertools` | Всегда писать `import itertools` в начале файла |
| Неверно задать диапазон перебора (например, не включить правую границу) | Помнить: `range(a, b)` — от a до b-1; для включения b писать `range(a, b+1)` |
| Перебирать упорядоченные пары вместо неупорядоченных (или наоборот) | Использовать `combinations` для неупорядоченных, `product` для упорядоченных |
| Счётчик не инициализирован до цикла | Всегда: `count = 0` перед циклом |
| Слишком большое пространство перебора — программа не успевает | Оценивать размер перебора до написания кода; оптимизировать условия |
| `print` внутри цикла вместо итогового вывода | Выводить результат **после** окончания всех циклов |
| **Задачи с исполнителем:** в условии «траектория содержит X» перемножают вместо сложения | Два отрезка → `f(start, X) * f(X, end)`, не `f(start, X) + f(X, end)` |
| **Задачи с исполнителем:** забывают запрет числа при разбиении на отрезки (тип 3) | Функции для каждого отрезка должны также исключать запрещённые числа |
| **Задачи с исполнителем:** не переворачивают знаки при движении «сверху вниз» | Если x > y: условие провала — `x < y`, рекуррентный вызов с уменьшающими командами |
| **Задачи с исполнителем:** рекурсия зависает без `@lru_cache` | При больших числах всегда добавлять `from functools import lru_cache` и `@lru_cache(maxsize=None)` |
